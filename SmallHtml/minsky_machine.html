Eine universelle Turingmaschine aus Zählern

Die Presets ④ und ⑤ laden dasselbe Minsky-Programm mit 112 Instruktionen, und zwar ganz ohne GOTO: nur INC, DEC und ein HALT. Es kennt keine bestimmte Turingmaschine. Welche Maschine es ausführt, steht ausschließlich in den Startwerten: die Regeltabelle als Zahl in TAB, das Band als zwei Zahlen in LINKS und RECHTS. Genau das macht das Programm universell: Ein festes Programm führt jede (binäre) Turingmaschine aus, die man ihm als Zahl übergibt.

Zusammen sind das 16 Zähler. Am Ende eines Zyklus stehen alle Arbeitsregister wieder auf 0.

Wie das Turingband in zwei Zahlen steckt

Das Band wird am Kopf in zwei Hälften geschnitten. Jede Hälfte ist ein Stapel: Die Zelle, die dem Kopf am nächsten liegt, ist oben. Ein Stapel aus Nullen und Einsen ist nichts anderes als eine Binärzahl, deren niedrigstes Bit oben liegt.

  Band:      … 0  0  1  0  1 [1] 0  1  1  0  0 …
                     └──── LINKS ──┘ ▲ └─ RECHTS ─┘
                                 Kopf

  LINKS  = Zellen links vom Kopf, nächste Zelle = Bit 0
         = 1·1 + 0·2 + 1·4               = 101₂ = 5
  RECHTS = Kopfzelle = Bit 0, dann nach rechts
         = 1·1 + 0·2 + 1·4 + 1·8         = 1101₂ = 13

Zwei Dinge fallen auf. Erstens liest man LINKS in Binärschreibweise genau so, wie das Band links vom Kopf aussieht (101), während RECHTS gespiegelt ist (1101 steht für das Bandstück [1]011). Zweitens ist das leere Symbol die 0: Das unendliche leere Band besteht einfach aus führenden Nullen, die in der Zahl nicht vorkommen. Deshalb genügen zwei endliche Zahlen für ein unendliches Band.

Alle Bandoperationen sind Multiplikationen und Divisionen mit 2, und die schreibt man in Minsky-Code als kleine Schleifen:

TM-OperationRechnung auf den Registern
LesenSYM := RECHTS mod 2, RECHTS := RECHTS div 2 (Kopfzelle vom Stapel nehmen)
w schreiben, rechtsLINKS := 2·LINKS + w (geschriebene Zelle wandert auf den linken Stapel)
w schreiben, linksRECHTS := 2·RECHTS + w, dann die oberste Zelle von LINKS herüberholen: RECHTS := 2·RECHTS + (LINKS mod 2), LINKS := LINKS div 2

Eine Halbierung ist zum Beispiel diese Schleife: zweimal DEC, einmal INC auf den Quotienten, und wenn die zweite Verringerung nicht mehr geht, war die Zahl ungerade.

DEC RECHTS →ende   # nichts mehr da: Rest 0
DEC RECHTS →ungerade
INC H              # H zählt die Hälfte
GOTO anfang
ungerade: INC SYM  # Rest 1

Marvin Minsky hat das Band in seinem Beweis genau so kodiert: zwei Stapel als Zahlen zu einer festen Basis. Primzahlpotenzen 2a·3b·5c·… braucht man erst im nächsten Schritt, wenn man all diese Register in nur zwei Zähler presst (siehe unten).

Die Regeltabelle als Zahl

Die Zustände werden von 1 bis n nummeriert, der Startzustand bekommt die 1, HALT die 0. Jede Regel „im Zustand q lese s → schreibe w, gehe in Richtung r, wechsle nach q′“ wird zu einer Ziffer

  Eintrag e = w + 2·r + 4·q′        (r = 1 für rechts, 0 für links)
  Position  i = 2·(q−1) + s
  TAB       = Σ eᵢ · BASISⁱ          mit BASIS = 4·(n+1)

Weil q′ ≤ n ist, gilt immer e < 4·(n+1). Jeder Eintrag passt also in genau eine Ziffer zur Basis BASIS. Fehlende Regeln sind die Ziffer 0, also „schreibe 0, gehe nach links, HALT“.

Beispiel Binär +1 (Preset ④): ein einziger Zustand A, also BASIS = 8.

Regelie
A 0 → 1 R H2·0+0 = 01 + 2·1 + 4·0 = 3
A 1 → 0 L A2·0+1 = 10 + 2·0 + 4·1 = 4

TAB = 3 + 4·8 = 35. Die Maschine läuft über die Einsen nach links, macht sie zu Nullen und setzt die erste Null auf 1. Auf dem Band 101[1] (dezimal 11, Kopf auf dem niedrigsten Bit) steht am Ende 1100 = 12. Startwerte: LINKS = 101₂ = 5, RECHTS = 1.

Der Busy Beaver mit zwei Zuständen (Preset ⑤) hat vier Regeln, BASIS = 12 und TAB = 11 + 9·12 + 5·144 + 3·1728 = 6023. Er startet auf leerem Band, schreibt vier Einsen und hält nach sechs Schritten.

Ein UTM-Zyklus = ein TM-Schritt

  1. Tabelle kopieren (Instruktionen 0–6): TAB nach X, denn das Nachschlagen zerstört die Zahl.
  2. Band lesen (7–14): SYM := RECHTS mod 2, RECHTS halbieren.
  3. Index bilden (15–22): I := 2·(ZUST−1) + SYM. ZUST und SYM werden dabei aufgebraucht.
  4. Regel nachschlagen (23–56): X so oft ganzzahlig durch BASIS teilen, bis I abgezählt ist. Der letzte Divisionsrest ist der gesuchte Eintrag. Die Division arbeitet im Pendelverfahren: BASIS wird beim Abziehen nach C umgeschichtet, beim nächsten Durchgang zurück. So muss BASIS nie kopiert werden.
  5. Eintrag zerlegen (57–66): zweimal halbieren liefert W, RICHT und den neuen ZUST.
  6. Schreiben und bewegen (67–106): je nach Richtung W auf einen der beiden Stapel legen und bei einer Linksbewegung eine Zelle von LINKS nach RECHTS holen.
  7. Abschluss (107–111): TMSCHRITT erhöhen. Ist der neue Zustand 0, hält die Maschine, sonst geht es zurück zu Instruktion 0.

In der Liste „Ablauf“ stehen diese Phasen als Überschriften über den Instruktionen.

Was das kostet

Minsky-Arithmetik ist unär: Eine Zahl um k zu verändern oder sie durch etwas zu teilen kostet ungefähr so viele Schritte, wie die Zahl groß ist. Jeder TM-Schritt kopiert und zerlegt die ganze Tabelle, also wächst der Aufwand mit dem Wert von TAB und damit exponentiell mit der Größe der simulierten Maschine.

Preset ④ kann man noch Schritt für Schritt verfolgen. Für den Busy Beaver ist der Knopf Turbo gedacht: Er rechnet ohne Animation und Protokoll und schreibt nur noch eine Zeile pro TM-Schritt.

Die Rechnung läuft mit gewöhnlichen JavaScript-Zahlen, die bis 253 exakt sind. Der Kodierer warnt, wenn TAB diese Grenze überschreitet. Praktisch begrenzt aber schon die Laufzeit die Größe: Ab etwa vier Zuständen dauert ein einzelner TM-Schritt Millionen Minsky-Schritte.

Und mit nur zwei Zählern?

Diese UTM benutzt 16 Zähler. Minsky zeigte zusätzlich, dass sich beliebig viele Zähler auf zwei reduzieren lassen: Alle Register wandern als Exponenten in eine Zahl 2X·3H·5C·7Q·…, und der zweite Zähler dient beim Multiplizieren und Dividieren mit diesen Primzahlen als Hilfsspeicher. Theoretisch funktioniert das mit genau diesem Programm. Die Zahlen würden aber schon bei Preset ④ weit jenseits von 253 liegen, und die Laufzeit würde noch einmal exponentiell wachsen.

Ganz ohne GOTO

Minskys Maschine kennt nur INC, DEC und HALT. Ein unbedingter Sprung lässt sich aber mit einem Register bauen, das nie erhöht wird: DEC NULL z findet NULL immer leer und springt deshalb immer nach z. Das kostet keine zusätzliche Instruktion und keinen zusätzlichen Schritt, nur ein zusätzliches Register. In der UTM sind so alle 32 Sprünge ersetzt.

mit GOTO               ohne GOTO
DEC A 3                DEC A 3
INC B                  INC B
GOTO 0         →       DEC NULL 0   # NULL ist immer 0
HALT                   HALT

Der Knopf GOTO → DEC NULL neben „Übernehmen“ wandelt jedes Programm im Editor so um, auch die Beispiele ① bis ③.

Will man auch das zusätzliche Register sparen, kann man an vielen Stellen ein Register nehmen, das dort ohnehin gerade 0 ist. Das funktioniert, macht das Programm aber schwer lesbar, weil jeder Sprung von einer Nebenbedingung abhängt. Ein festes NULL ist die saubere Lösung.

In Minskys eigener Formulierung stellt sich die Frage gar nicht: Dort nennt jede Instruktion ihren Nachfolger ausdrücklich, also INC(r, weiter) und DEC(r, weiter, wenn_null). Ein Programm ist ein Graph, und Sprünge sind kostenlos. Erst die Schreibweise „eine Instruktion pro Zeile, weiter mit der nächsten“ macht ein GOTO bequem.
