Platte direkt aus der DiskStation? → Reiter Synology-Platte.

Worum es geht

Hier liest du eine Festplatte, die du aus einer Synology DiskStation ausgebaut und per USB an einen Linux-Rechner gehängt hast. Die Seite selbst darf als Webseite keine Platten einhängen – dafür gibt es ein kleines Skript, das sie dir passend zu deiner Platte erzeugt. Danach übernimmt die Seite alles Weitere: Freigaben finden, Schlüssel zuordnen, entschlüsseln, sichern.

Schritt 1–5 laufen nur lesend: Das RAID wird mit --readonly gestartet, ext4 mit ro,noload eingehängt, LVM-Metadaten bleiben unverändert. Auf die Synology-Platte wird nichts geschrieben – das tut nur Schritt 6, das endgültige Löschen, und nur nach ausdrücklicher Bestätigung. Für Schritt 4 und 5 brauchst du Chrome, Chromium oder Edge (Firefox kann keine Ordner Ebene für Ebene lesen und keine Ordner beschreiben).

1 Platte anschließen und erkennen

Platte per USB anschließen, ein Terminal öffnen und diesen Befehl ausführen:

lsblk -P -o NAME,PKNAME,TYPE,SIZE,FSTYPE,FSVER,LABEL,UUID

Die komplette Ausgabe hier einfügen (die Ausgabe von lsblk -f geht auch):

Ohne Einfügen sucht das Skript die Synology-Partitionen selbst.

2 Einhängen mit dem Skript

Lade das Skript herunter und starte es im Terminal. Es installiert bei Bedarf mdadm, lvm2 und bindfs, setzt das RAID zusammen, aktiviert LVM, hängt das Volume unter /mnt/syno ein und stellt es unter /mnt/syno-user für deinen Benutzer lesbar bereit.

cd ~/Downloads
sudo bash synomount.sh            # einhängen
sudo bash synomount.sh status     # nachsehen, was läuft
sudo bash synomount.sh stop       # wieder aushängen
sudo bash synomount.sh wipe       # Platte endgültig löschen – siehe Schritt 6

    6 Platte sicher löschen (vor Rücksendung oder Weitergabe)
    

    Formatieren reicht nicht – dabei werden nur die Verwaltungsdaten neu angelegt, die Dateien
bleiben lesbar. Das Skript überschreibt deshalb die ganze Platte einmal. Das genügt bei
heutigen Platten (so auch die NIST-Richtlinie SP 800-88); mehrere Durchgänge bringen nichts mehr.
    

    Als Muster nimmt es Nullen (Standard) oder mit --zufall einen
Zufallsstrom (AES-256-CTR mit Einmal-Schlüssel). Beides ist gleich sicher. Zufall hat nur den
Vorteil, dass man der Platte nicht ansieht, dass sie gelöscht wurde. Der Schlüssel steht nur während des
Löschens in einer Statusdatei (damit Fortsetzen und Prüfen gehen) und wird am Ende gelöscht.
    

    Erst prüfen: Ist die Platte wirklich defekt?
    

    DSM meldet „Problem mit der Platte“ aus ganz verschiedenen Gründen – nicht jeder heißt, dass die
Platte kaputt ist. Ob sie zurück in die Garantie, weiterverwendet oder entsorgt wird, entscheidet sich
an den SMART-Werten. Smartmontools installieren und die Werte auslesen:
    

    sudo apt install smartmontools
sudo smartctl -a -d sat /dev/sdX          # -d sat ist für USB-Gehäuse nötig
    

    Die komplette Ausgabe hier einfügen – die Seite bewertet sie:
    


    

    


    Spickzettel: alle Befehle zur Platten- und Sektoranalyse

    Für /dev/sdX immer die richtige Platte einsetzen. -d sat braucht man bei USB-Gehäusen;
bei intern angeschlossenen SATA-Platten kann es entfallen, bei NVMe-SSDs (/dev/nvme0n1) weglassen.
Nichts in den Abschnitten 1–4 verändert Daten auf der Platte.
    


    1. Platte finden und erkennen
    

    lsblk -d -o NAME,SIZE,MODEL,SERIAL,TRAN      # alle Platten: Größe, Modell, Seriennr., Anschluss (usb/sata/nvme)
sudo dmesg | tail -30                        # direkt nach dem Anstecken: welcher Name (sdb, sdc …) vergeben wurde
sudo apt install smartmontools hdparm        # Werkzeuge einmalig installieren
    


    2. SMART-Werte lesen
    

    sudo smartctl -i -d sat /dev/sdX             # Kurzinfo: Modell, Seriennr., Firmware, SMART an/aus
sudo smartctl -H -d sat /dev/sdX             # nur Gesamturteil PASSED/FAILED
sudo smartctl -a -d sat /dev/sdX             # alles Wichtige – diese Ausgabe oben einfügen
sudo smartctl -x -d sat /dev/sdX             # noch ausführlicher (Temperaturverlauf, Geräte-Statistik)
sudo smartctl -A -d sat /dev/sdX | grep -E "^ *(5|9|197|198|199) "
                                             # nur die fünf entscheidenden Werte
sudo smartctl -l error -d sat /dev/sdX       # Fehlerprotokoll der Platte
sudo smartctl -l scttemp -d sat /dev/sdX     # Temperatur und Verlauf
    


    3. Selbsttests (laufen in der Platte, der Rechner kann weiterarbeiten)
    

    sudo smartctl -c -d sat /dev/sdX             # wie lange die Tests dauern („polling time“)
sudo smartctl -t short -d sat /dev/sdX       # kurzer Test, ca. 2 Minuten
sudo smartctl -t long -d sat /dev/sdX        # langer Test: liest jeden Sektor, 2 TB ≈ 4–5 Stunden
sudo smartctl -l selftest -d sat /dev/sdX    # Ergebnis ansehen (oberste Zeile = neuester Test)
sudo smartctl -a -d sat /dev/sdX | grep -A1 "Self-test execution"
                                             # läuft noch? „xx% of test remaining“
sudo smartctl -X -d sat /dev/sdX             # laufenden Test abbrechen
    

    „Completed without error“ = gut. „Completed: read failure“ mit einer Zahl unter
LBA_of_first_error = an dieser Stelle ist ein Sektor defekt.
    


    4. Oberfläche selbst lesen (findet unlesbare Stellen, nur lesend)
    

    sudo badblocks -sv -b 4096 /dev/sdX          # liest jeden Block, zeigt Fortschritt, listet defekte Blöcke
sudo badblocks -sv -b 4096 -o defekt.txt /dev/sdX
                                             # dasselbe, defekte Blöcke in eine Datei schreiben
sudo dd if=/dev/sdX of=/dev/null bs=1M status=progress
                                             # schnellste Leseprobe: bricht an der ersten defekten Stelle ab
sudo dmesg | grep -iE "I/O error|Medium Error|UNC"
                                             # Lesefehler, die der Kernel dabei gemeldet hat
sudo smartctl -A -d sat /dev/sdX | grep -E "^ *(5|197|198) "
                                             # danach: haben sich ausgemusterte/wartende Sektoren verändert?
    

    badblocks ohne Zusatz ist nur lesend. Niemals badblocks -w auf einer Platte mit
Daten verwenden – das überschreibt alles (das ist ein Schreibtest, praktisch ein Löschen).
Mit -n testet badblocks schreibend, stellt die Daten aber wieder her – dauert sehr lange und darf
nur auf nicht eingehängten Platten laufen.
    


    5. Secure-Erase-Fähigkeit prüfen (für das Löschen unten)
    

    sudo hdparm -I /dev/sdX | grep -A8 Security  # „supported“ + „not frozen“ = ATA Secure Erase möglich
    


    Faustregel zum Bewerten
    

      
  
    • ID 197 oder 198 über 0, oder ein Selbsttest mit „read failure“ → Platte ist defekt, Daten runter.
      • 
  
    • ID 5 über 0, aber stabil → Platte hat schon Sektoren getauscht; beobachten (Werte in ein paar Wochen vergleichen).
  Steigt die Zahl weiter → austauschen.
      • 
  
    • ID 199 steigt → Kabel/Steckplatz prüfen, die Platte selbst ist meist in Ordnung.
      • 
  
    • Alles 0, Selbsttests ohne Fehler → Platte gesund; dann ist ein DSM-Hinweis eher das RAID oder das Alter.
      • 

    

    


    Was die wichtigsten SMART-Werte bedeuten

    
  
    IDWertBedeutung
    
  
    5Reallocated_Sector_CtAusgemusterte Sektoren. 0 = keine. Steigt der Wert, verschleißt die Oberfläche;
    an den alten Inhalt dieser Sektoren kommt nur ATA Secure Erase.
    
  
    197Current_Pending_SectorSektoren, die sich gerade nicht lesen lassen und auf Ersatz warten.
    Über 0 = echtes Warnzeichen.
    
  
    198Offline_UncorrectableBeim Selbsttest unlesbare Sektoren. Über 0 = Warnzeichen.
    
  
    199UDMA_CRC_Error_CountÜbertragungsfehler zwischen Platte und Rechner – meist Kabel oder
    Steckplatz, nicht die Platte selbst.
    
  
    9Power_On_HoursBetriebsstunden. 8.760 h = ein Jahr Dauerbetrieb. NAS-Platten halten oft
    5–8 Jahre; danach steigt das Ausfallrisiko.
    
  
    4 / 12Start_Stop / Power_CycleAnlauf- und Einschaltvorgänge – hohe Werte kommen vom Ruhezustand
    der DiskStation und bedeuten Verschleiß, aber keinen Defekt.
    
  
    1 / 7Raw_Read / Seek_Error_RateRohwerte sind herstellerspezifisch und oft riesig – nicht
    beachten. Entscheidend ist nur, ob VALUE auf oder unter THRESH fällt.
    

    

    Grundregel: Ein Wert ist erst „ausgefallen“, wenn VALUE ≤ THRESH (bei THRESH > 0) oder unter
WHEN_FAILED etwas steht. Im Selbsttest-Protokoll zählt die Lebenszeit nur bis 65.535 Stunden und fängt dann
wieder bei 0 an – kleine Zahlen dort sind bei alten Platten kein Widerspruch.
    

    

    Was DSM mit „Problem mit der Platte“ meinen kann

      
  
    • Volume/Speicherpool „beeinträchtigt“ (degraded): Im RAID fehlt eine Platte. Das betrifft oft gar
  nicht die Platte, die du in der Hand hast, sondern die andere. Merkmal hier: mdadm meldet
  „started with 1 drive (out of 2)“.
      • 
  
    • „Fehlerhafte Sektoren“ / Status „Warnung“: SMART-ID 5 oder 197 über 0.
      • 
  
    • Hohe Betriebsdauer: Neuere DSM-Versionen warnen bei alten Platten, auch wenn sie fehlerfrei laufen.
      • 
  
    • Verbindungsfehler: ID 199 steigt – Steckplatz, Kabel oder Netzteil, nicht die Platte.
      • 

    

    

    Langer Selbsttest – die gründlichste Prüfung

    Die Platte liest dabei jeden Sektor (bei 2 TB etwa 4–5 Stunden, die genaue Zeit steht unter
„Extended self-test routine recommended polling time“). Danach zeigt smartctl -a das Ergebnis
im Selbsttest-Protokoll – „Completed without error“ ist gut, „read failure“ mit einer LBA ist ein echter Defekt.
    

    sudo smartctl -t long -d sat /dev/sdX     # Test starten (läuft in der Platte)
sudo smartctl -a -d sat /dev/sdX          # später: Ergebnis ansehen
    

    Manche USB-Gehäuse schicken die Platte nach einigen Minuten in den Ruhezustand und brechen
den Test damit ab („Aborted by host“). Dann hilft es, nebenher etwas von der Platte zu lesen, z. B.
sudo dd if=/dev/sdX of=/dev/null bs=1M status=progress.
    

    

    Garantie, Weiterverwenden oder Entsorgen?

      
  
    • Garantie: NAS-Platten haben je nach Serie meist 3 Jahre (z. B. WD Red/Red Plus,
  Seagate IronWolf), Profi-Serien 5 Jahre. Genau prüfen über die Seriennummer beim Hersteller. Der Hersteller
  will meist einen SMART-Befund sehen – das Löschen ändert die SMART-Werte nicht, er bleibt nachweisbar.
      • 
  
    • Weiterverwenden: Gesunde, aber alte Platten taugen gut als zusätzliche Sicherungsplatte –
  nicht als einziger Ort für wichtige Daten.
      • 
  
    • Entsorgen oder verkaufen: vorher löschen wie unten beschrieben. Bei 0 ausgemusterten
  Sektoren erfasst das Überschreiben die ganze Platte.
      • 

    

    


    Dann löschen
    

    Vorher abhaken:
    

      
  
    • Alle Freigaben gesichert (Schritt 4) und ein paar Dateien in der Sicherung probeweise geöffnet.
      • 
  
    • .key-Dateien bzw. Passwörter der Freigaben aufgehoben, falls du die Sicherung noch einmal brauchst.
      • 
  
    • Alles ausgehängt: sudo bash synomount.sh stop
      • 
  
    • Für die SMART-Anzeige: sudo apt install smartmontools hdparm
      • 

    

    lsblk -d -o NAME,SIZE,MODEL,SERIAL,TRAN   # welche Platte ist es? (TRAN = usb)
sudo bash synomount.sh wipe               # löscht die erkannte Synology-Platte
sudo bash synomount.sh wipe /dev/sdX      # oder ausdrücklich angeben
sudo bash synomount.sh wipe --zufall      # Zufallsmuster statt Nullen
    

    So schützt dich das Skript vor dem falschen Gerät:
    

      
  
    • Es löscht nur ganze Platten, auf denen eine Synology-RAID-Partition liegt – deine System-SSD
  oder eine andere Platte lehnt es ab.
      • 
  
    • Es bricht ab, solange auf der Platte etwas eingehängt oder ein RAID/LVM aktiv ist.
      • 
  
    • Es zeigt Modell, Seriennummer, Größe, Anschluss und die SMART-Zahl der bereits
  ausgemusterten Sektoren an. Steht dort 0, erfasst das Überschreiben die komplette Platte.
  Erst wenn du die
  Seriennummer abtippst, geht es los. Vergleiche sie mit dem Aufkleber der Platte.
      • 

    

    Während des Löschens:
    

      
  
    • Eine Anzeige zeigt Fortschritt, Tempo und Restzeit. Bei 2 TB über USB dauert das etwa 3–5 Stunden.
      • 
  
    • Abbrechen mit Strg+C ist erlaubt. Derselbe Befehl setzt später an der Stelle fort.
  Da dann die Synology-Kennung schon gelöscht ist, gib die Platte dabei ausdrücklich an
  (wipe /dev/sdX) – das Skript erkennt sie an der Seriennummer wieder. Es setzt mit dem
  ursprünglichen Muster fort; gibst du ein anderes an (--zufall bzw. --null), fragt es, ob es
  fortsetzen oder neu von vorn beginnen soll.
      • 
  
    • Defekte Stellen (die SMART-Fehler) überspringt es Stück für Stück, statt abzubrechen, und
  listet sie am Ende auf.
      • 
  
    • Zum Schluss liest es Anfang, Ende und 40 zufällige Stellen zurück und prüft, dass dort nur Nullen stehen.
      • 

    

    Und die „ausgemusterten“ Sektoren?
  
    Eine Platte mit SMART-Fehlern legt defekte Sektoren still und ersetzt sie durch Reserve. Schreibt man
  danach an diese Stelle, landet es in der Reserve – der alte Sektor ist für kein Programm mehr
  erreichbar, weder mit Nullen noch mit Zufall. Dort könnten Bruchstücke stehen (bei verschlüsselten
  Freigaben nur Datensalat). Wie viele es sind, zeigt das Skript als SMART-Wert „ausgemustert (ID 5)“.
    
  
    Löschen kann sie nur die Platte selbst: ATA Secure Erase. Das Skript prüft vor dem Überschreiben,
  ob die Platte das kann, und fragt dann nach – auch über USB, mit Warnung: Manche USB-Gehäuse brechen
  den langen Befehl ab, dann bleibt die Platte mit dem Passwort synowipe gesperrt; das Skript
  nennt dir den Entsperrbefehl. Meldet es „nicht verfügbar“, reicht das Gehäuse den Befehl nicht durch –
  intern per SATA angeschlossen klappt es meist (steht dort „frozen“, hilft oft Abstecken und Neuanstecken
  im laufenden Betrieb). Wem selbst dieses Restrisiko zu groß ist, bleibt nur die mechanische Zerstörung –
  dann allerdings ohne Garantietausch.
    


    Wenn es hakt
    

    „started with 1 drive (out of 2)“
  
    Normal, wenn die DiskStation zwei Platten im RAID1/SHR hatte und du nur eine angeschlossen
  hast. Beide Platten enthalten dieselben Daten. Bei RAID5 aus drei oder mehr Platten reicht eine
  einzelne Platte dagegen nicht.
    

    „WARNING: PV … is using an old PV header“
  
    Harmlos. Bitte nicht den Vorschlag „modify the VG“ befolgen – das würde auf
  die Platte schreiben.
    

    Der Auswahldialog lässt /mnt/syno-user nicht zu oder zeigt nichts
  
    Prüfe mit sudo bash synomount.sh status, ob /mnt/syno-user eingehängt ist.
  Ohne die bindfs-Sicht kann der Browser die Dateien von root nicht lesen. Chrome sperrt außerdem
  einige Systemordner – /mnt/… gehört nicht dazu.
    

    Schlüssel passt bei keiner Freigabe
  
    Das Passwort einer verschlüsselten Freigabe ist ein eigenes Passwort, nicht das DSM-Anmeldepasswort.
  Die .key-Datei ist der sichere Weg. Bei AES-192-Freigaben (selten) braucht es Firefox
  im Browser-Reiter; Chrome kennt AES-192 nicht.
    

    btrfs statt ext4
  
    Das Skript erkennt das selbst und hängt btrfs mit ro bzw. ro,rescue=nologreplay
  ein. Falls auch das scheitert: sudo dmesg | tail zeigt den Grund.
